# Обязательные правила создания новых демо-сайтов

Этот файл — постоянная инструкция для AI-ассистентов и Codex при работе с репозиторием **demo-sites**. Прочитать до создания или изменения любого макета.

## Цель

Создавать высококачественные демонстрационные сайты стоматологических и других локальных компаний. Сохранять лучшие функции предыдущих проектов, адаптировать фирменные цвета и фактуру, не выдумывать сведения о бизнесе.

## Обязательная база нового сайта

1. **Интерактивная анатомическая 3D-модель зуба для стоматологии**, восстановленная из репозитория `dantist-1-site`. Размещать в главном экране с реальными рабочими кнопками «Разобрать», «Собрать», «Вращение» и управлением мышью / touch. Реализация: `assets/tooth-3d.js`. Нельзя заменять её просто картинкой или 2D SVG без согласования. 2D SVG разрешён только как fallback при отсутствии WebGL/Three.js.
2. Крупный профессиональный первый экран, чёткий CTA для звонка/записи, навигация, адаптивное меню, каталог услуг с поиском/фильтрами, блок о клинике, фотогалерея с увеличением, FAQ, контакты и мобильная версия.
3. Фотографии только подтверждённой клиники из выданных пользователем материалов; не подменять случайными фотографиями врачей или интерьеров. Сохранять фирменные цвета из логотипа, вывески, фотографий, сайта/соцсетей.
4. Названия услуг, лицензии, квалификацию врачей, цены, часы, рейтинги и отзывы брать из подтверждённых источников. Если нет подтверждения, не придумывать. Для неуточнённых услуг и условий — явная пометка «предварительный перечень / уточняйте».
5. **Яндекс Карты и отзывы подключать по наличию подтверждённых оценок в Яндексе:** если у компании есть подтверждённые отзывы/рейтинг в Яндекс Картах и заказчик хочет их показать, добавить раздел отзывов (официальный виджет по возможности), ссылку на оригинальную карточку и (если достоверны) рейтинг и дату проверки. НИКОГДА не показывать чужой рейтинг и не выдавать 2ГИС за Яндекс. Если оценки Яндекса отсутствуют или не подтверждены — не создавать пустой раздел рейтинга/отзывов и не связывать сайт с Яндекс Картами без явной просьбы пользователя. Геоадрес можно отобразить отдельно.
6. Различать «число отзывов» и «число оценок»; не показывать статическую устаревающую цифру как актуальную. Если данные получены из сторонней сводки, подписывать источник и дату и не утверждать, что это онлайн-рейтинг.
7. Все кнопки и ссылки должны вести к реальным действиям. Никаких фиктивных заявок, форм с имитацией отправки, фальшивых отзывов/сертификатов/акций. Обязательно помечать неофициальный демонстрационный статус.
8. Хранить каждый новый сайт в отдельной папке `<slug>/index.html` внутри **одного** репозитория; общие компоненты — в `assets/`. Ссылки на сайты добавлять в корневые `index.html` и `README.md`.
9. Не удалять функции предыдущих сайтов при редизайне: перед публикацией сравнить с `dantist-1-site` и `intelstom-site`. Если что-то невозможно/неуместно, объяснить и отметить исключение.
10. Перед сдачей проверить адаптивность, консольные ошибки, WebGL fallback, работу «Разобрать/Собрать/Вращение», фильтры услуг, фотогалерею, звонок, внешние ссылки, 404 и публикацию через GitHub Pages.

## Текущие сайты и различия

- `almaklinik/`: графит и золото. В открытой выборке подтверждены лишь отзывы 2ГИС; Яндекс-рейтинг не показывать и ссылки на Яндекс Карты не добавлять без новых проверенных данных.
- `arovana/`: бирюза и зелёный. По выборке стороннего обзора от 07.10.2026 было 2 текстовых отзыва на Яндекс Картах; на сайте раздел отзывов должен вести к действующей карточке. Не выдавать исторические числа за живые.

## Ссылки на технические составляющие

- `assets/site.css` — общая стилизация с фирменными темами;
- `assets/site.js` — интерактивные элементы интерфейса;
- `assets/tooth-3d.js` — оригинальный трёхмерный зуб на Three.js;
- `SITE_STANDARD.md` — подробный чек-лист качества и источников;
- `README.md` — каталог опубликованных сайтов.

Если пользователь просит «по образу и подобию предыдущих», применяй все вышеперечисленные правила **по умолчанию**.
